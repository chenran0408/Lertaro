# Beta19：动作菜单不抢输入法组合按键

三个搜索窗口共用的动作菜单按键处理会将 `ImeProcessedKey` 展开为 ASCII 字母。筛选框为空时，拼音尚未提交的首字母可能匹配菜单助记键并执行动作。

本版只在助记键选择阶段将 `Key.ImeProcessed` 留给输入法，不修改全局实际按键展开，也不跳过前置的可配置组合快捷键。

- 8 项定向测试通过，覆盖真实 WPF KeyEventArgs 的 IME 标记、匹配到的菜单项、非空筛选和修饰键行为。
- 独立 WPF 测试窗口直接引用编译后的生产方法和真实 ActionMenuItem。zh-CN 模式中 `n` 为 `ImeProcessed/Actual=N` 时动作计数保持 0；继续输入 `ni` 并按 Enter 后收到提交的 TextInput。
- 同窗口的 Ctrl+N 仍经生产快捷键匹配器识别；禁用该字段的 IME 后，普通 N 执行相同菜单项，动作计数变为 1。

这些检查针对动作菜单的字母助记键，不代表所有输入法和所有自定义双击按键组合已逐一验收。
