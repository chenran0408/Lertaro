# Beta 5 验证记录

## 改动

Rust 压缩构建不再把完整基础快照和新增行一起重新排序。基础行本来已经按完整 UInt128 ID 排序，因此现在只排序新增行，再与基础行合并；相同 ID 仍保持基础硬链接在前、新增行按原顺序在后。

同时扩展了 `Tools/CompactionBenchmark`，可以指定每轮新增行数，用于测试批量变更，而不只测试单行变更。

## 结果

使用 100,000 行基础索引、10 轮、每轮新增 100 行，在同一台 Windows x64 机器上运行：

- 修改前压缩中位数：`32.20 ms`
- 修改后压缩中位数：`30.52 ms`
- 最终行数：两次均为 `101,000`
- 这是单机样本，不把它当作所有索引分布的固定加速比例；主要收益是避免随基础行数增长的全量排序。
