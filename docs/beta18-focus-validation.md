# Beta18：取消过期的搜索焦点请求

问题通过真实 WPF Dispatcher、Window 和 TextBox 复现：首次唤起的前景确认延迟，窗口关闭后迅速重开，新查询要求光标放在末尾，但旧请求约 200 ms 后将其重新全选。下一次输入因此可能替换整条查询。

修复使用单个待执行计时器，新请求或隐藏会取消旧请求。尚未开始的窗口激活回调沿用控制器已有的可见性令牌，隐藏或新召唤后失效；没有再建立一套代次机制。

真实 WPF 回归测试覆盖隐藏／取消／重开、新请求替换旧请求，以及全选与末尾光标的优先级。目标测试 7/7 通过。独立复现中，同一操作顺序从错误的 `Selection=0+9, Caret=0` 恢复为 `Selection=9+0, Caret=9`。

这些检查验证延迟焦点回调的顺序和选区，不代表所有输入法、全屏应用或管理员窗口组合已完成端到端验收。
